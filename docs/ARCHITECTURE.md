# Архитектура

```text
game.json
  → задаёт идентичность CoC2, Steam/App/процесс, пути и строгие CDP target matchers
CoC2 Translator.app / CoC2 Translator.exe
  → на Windows запускает credential-backed helper и CoC2 напрямую
  → на macOS запускает Windows-версию CoC2 только через CrossOver
  → держит Electron remote debugging только на loopback той же ОС
  → контроллер выбирает только совпавшую CoC2 page и внедряет translator.bundle.js
translator.bundle.js
  → core + languages + providers + generated game config + CoC2 adapter + runtime
runtime
  → наблюдает видимый/изменённый DOM → кэш → Google или OpenAI-compatible → Text-узлы
```

Это исключительно runtime/realtime DOM-переводчик. В проекте нет чтения, извлечения или изменения ассетов игры, статического translation pack, Workbench, массовой обработки каталогов, выбора игр либо логики другого игрового продукта.

## Слои

- `src/translation-core.js`, сгенерированный из `src/languages.json` каталог, `src/providers.js`, `src/interface-presets.js`, `src/panel-view.js` и `src/translator-runtime.js` — общее браузерное ядро;
- `src/games/coc2/game.json` — единый источник идентичности, запуска, путей, namespace и палитры `theme`;
- `src/games/coc2/adapter.js` — только DOM-правила CoC2;
- `src/openai-compatible.json` — единая конфигурация prompt, preset, параметров и маршрутов OpenCode Chat Completions/Responses/Messages;
- `src/local_service.py` — аутентифицированный loopback helper для credential vault и OpenAI-compatible HTTP;
- `src/controller/main.swift` и платформенные лаунчеры — CDP-инъекция и lifecycle.

`launchStrategy` остаётся равной `electron-cdp`; неизвестная стратегия отклоняется сборкой. Контроллер требует совпадения title или URL из манифеста и не внедряется в произвольную Electron-страницу.

Runtime откладывает инициализацию до появления `documentElement` и `body`. Общий pending-маркер не допускает повторной инициализации, если CDP доставляет bundle ещё раз до `DOMContentLoaded`; панель и DOM-observer поэтому создаются ровно один раз.

`src/languages.json` хранит единый 30-язычный каталог VN Revival. Сборка генерирует из него браузерный модуль, исключая ручные копии списка. Для первой загрузки без сохранённых настроек runtime выбирает `en`; корректный последующий выбор пользователя сохраняется.

Галочка `UI` рядом с выбором языка применяет к Shadow DOM панели только встроенный `INTERFACE_PRESETS`. Интерфейсные строки не проходят через provider registry, сетевые запросы или IndexedDB; неизвестный preset безопасно возвращается к английскому. Переключатель сохраняется отдельно от языка и не влияет на перевод игрового DOM.

## DOM-проход

Текстовые контейнеры регистрируются один раз. `IntersectionObserver` сообщает о приближении блока к viewport, а `MutationObserver` ставит в очередь изменённые React-узлы и блоки, показанные сменой `class`, `style`, `hidden` или ARIA-состояния. Tooltip-контейнеры, уже присутствующие в DOM, допускаются в фоновую очередь даже вне viewport и до наведения; остальные скрытые элементы по-прежнему исключаются. Текст `<option>` оценивается по видимости родительского `<select>`, потому что нативное окно списка не имеет обычной DOM-геометрии; сами элементы и выбранное значение остаются исходными игровыми контролами. Автопроход не повторяет полный `TreeWalker` на каждой прокрутке. В старом Chromium используется scroll-fallback.

При `document.hidden` таймер останавливается и активный запрос отменяется. После возвращения видимые контейнеры снова ставятся в очередь. Ручной `Translate` или `Ctrl+Shift+T` запускает текущий проход; повторное действие вызывает `AbortController`.

Блокировка очереди охватывает загрузку сайтной конфигурации, проверку статуса провайдера и перевод. Отмена во время предварительной проверки не допускает последующего запуска переводных запросов. При удалении поддерева runtime освобождает записи перевода, оформления и observer; исходные текст и оформление восстанавливаются для возможной повторной вставки. Перемещение внутри живого DOM сохраняет текущий перевод.

Слоты сохранения, формы, редактируемые элементы, служебные блоки и распознанные имена игрока исключаются адаптером и ядром. Имя, уже включённое игрой в цельную сюжетную строку, отделить от предложения невозможно.

## Контекст без замены HTML

Соседние `Text`-узлы логического блока объединяются маркерами `VRCTXSEP…X`. Перевод разбирается по этим маркерам и записывается обратно в существующие узлы. `innerHTML`, DOM-элементы и обработчики не заменяются. Повреждённые или переставленные маркеры отклоняются; runtime повторяет этот блок по отдельным фрагментам.

OpenAI-compatible объединяет соседние задания `story` и `ui` одного DOM-контейнера в крупные блоки, а `control` — в группы элементов управления. Предел одного пакета: 12 исходных блоков, 48 Text-фрагментов и 6000 байт UTF-8 с маркерами. Отдельный слишком большой абзац проходит существующий splitter. Tooltip и исходный текст с буквальными служебными маркерами не объединяются. Порядок следует исходному DOM, включая повторяющиеся сюжетные абзацы; интерфейсные дубликаты по-прежнему используют один перевод.

Внутренние маркеры составных абзацев перенумеровываются на время общего запроса. Инструкция сообщает модели границы абзацев, чтобы сюжет переводился связно, а элементы управления — независимо. Ответ сначала проверяется целиком, затем разбирается на исходные абзацы с восстановлением их собственных маркеров. Кэш остаётся по исходным абзацам/элементам: в запрос включаются только отсутствующие блоки, поэтому при частичном попадании в кэш модель видит только недостающую часть сцены.

Обновления `story` и `ui`, включая попадания в кэш, накапливаются до готовности всего блока и применяются синхронно. Изменение или удаление любого исходного узла отменяет применение этого блока; конфигурация также должна совпадать с началом прохода. Перестановка DOM-узлов во время запроса не меняет привязку перевода к самим узлам. Повреждённый общий ответ не кэшируется, отсутствующие исходные блоки повторяются отдельно. Если этот повтор прерывается, успешные результаты остаются в кэше; повторная попытка включает всю ещё не показанную группу, но отправляет только недостающие переводы. HTTP 400 и другие постоянные отказы останавливают очередь без разделения запроса.

Исходные атрибуты и inline-стили сохраняются до применения перевода. При смене языка или конфигурации runtime возвращает исходный текст, `lang`, `dir`, выравнивание, line-height, font-family, высоту и переносы перед повторным переводом.

## Провайдеры

Реестр `src/providers.js` содержит ровно два варианта:

- `google` — публичный endpoint без API-ключа;
- `openai-compatible` — от одного до восьми параллельных запросов через локальный helper; пользовательское значение по умолчанию — четыре.

OpenAI-compatible включает preset OpenCode Go, OpenCode Zen, OpenRouter, DeepSeek, LM Studio и Custom. Перед первым запросом для выбранной локали runtime просит loopback-helper получить с фиксированного HTTPS endpoint VN Revival версионированный системный prompt и полный локализованный глоссарий игры. Helper проверяет host после redirect, размер, схему, полноту локали и безопасный формат каждой пары; недоступный или неправильный ответ не блокирует перевод, а оставляет комплектный prompt и локальные пользовательские дополнения. Runtime сохраняет preset, Base URL, model ID, необязательный пользовательский override prompt, дополнительный пользовательский словарь, reasoning effort и отдельный лимит параллельных запросов. Пользовательская пара заменяет одноимённую пару сайта. Verbosity фиксируется runtime на `low`; при явной неподдержке helper удаляет параметр и повторяет запрос с default провайдера. Лимит параллельности влияет только на число workers и не входит в payload или cache variant. Для словаря из строк `source = translation` передаются только записи, совпавшие с исходным фрагментом после нормализации регистра, Unicode и пробелов; произвольные пользовательские инструкции сохраняются целиком, но не заставляют отправлять весь сайтный глоссарий; шаблон поддерживает `{targetName}` и `{target}`, которые helper заменяет выбранным языком. Открытие model picker вызывает `GET /models`; единый безопасный select закрепляет бесплатные модели сверху, сортирует обе группы по алфавиту и оставляет отдельный пункт для ручного ID. OpenCode Go показывает весь актуальный каталог провайдера без локального фильтра; OpenCode Zen оставляет только известные совместимые модели. Для Go helper направляет документированные модели в `POST /chat/completions`, `POST /responses` или Anthropic-compatible `POST /messages`. Responses использует `instructions`/`input`, вложенные reasoning/text и разбирает `output_text`; Messages передаёт system/user content и разбирает текстовые content-блоки. Неизвестные новые ID по умолчанию пробуются через Chat Completions. Временные отказы повторяются с exponential backoff и `Retry-After`, а исчерпанный rate limit останавливает оставшуюся очередь вместо серии бесполезных запросов.

Helper сначала просит JSON Schema. При явном отказе endpoint от этого формата он
переходит на `json_object`, а при ещё одном явном отказе — на запрос без
`response_format`. Он принимает объект `translation`, fenced JSON либо непустой
plain text, но затем обязательно проверяет контекстные маркеры. Возвращаемое
поле `reviewed: false` и UI прямо обозначают, что технически валидный машинный
результат не является редакторски проверенной или одобренной локализацией.
Optional model-параметры отправляются только при выбранном значении. Если HTTP
400 явно называет один из них неподдерживаемым, helper удаляет его и повторяет
тот же запрос. Другие ошибки не запускают этот fallback.
Известные безопасные причины upstream-отказа классифицируются без возврата
сырого provider message: в частности, gateway HTTP 400/401 с недоступной или
неподдерживаемой моделью становится `openai_model_unavailable`, а не локальным
502 или ошибкой ключа.

## Секреты и сеть

`src/local_service.py` слушает только `127.0.0.1`, требует одноразовый токен запуска и ограничивает размеры запросов/ответов. Публичную конфигурацию перевода он получает только с `https://vnrevival.fun`, не следует redirect на другой host и не передаёт сайту игровой текст, секреты или пользовательские overrides. API-ключ передаётся helper один раз при сохранении и затем очищается из поля панели. JavaScript игры не получает сохранённый ключ обратно.

Каждый нормализованный Base URL получает отдельную credential identity на основе SHA-256:

- macOS — Keychain generic password;
- Windows — Credential Manager generic credential.

Секрет не попадает в командную строку, URL, `localStorage`, IndexedDB или переводный кэш. Внешний запрос передаёт его только в заголовке авторизации: `Authorization: Bearer` для Chat Completions/Responses и `X-API-Key` для Messages.

Общий HTTP transport helper проверяет каждый redirect до отправки следующего запроса. Смена схемы, host или порта, а также credentials в адресе перенаправления запрещены; относительные переходы внутри того же origin разрешены. Это ограничение действует и для провайдера, и для загрузки публичной конфигурации.

Custom URL отклоняется при наличии credentials, query, fragment, управляющих символов или `..`. Удалённый endpoint обязан использовать HTTPS. HTTP разрешён только для точного `localhost` либо loopback IP, включая IPv4/IPv6. Локальный helper также доступен runtime только по `http://127.0.0.1:<port>` с валидным токеном.

## Кэш

IndexedDB хранит полный кэш; RAM-кэш — LRU на 20 000 записей. V3-ключ включает `game-id`, provider и language. Для OpenAI-compatible используется v4: fingerprint включает preset, Base URL, model ID, параметры модели, версию, полный текст системного prompt и применимые к исходному тексту записи словаря. Смена endpoint, модели, параметров или инструкции изолирует кэш; правка посторонних терминов сохраняет готовые переводы. Для составного контекста зависимость от словаря считается по всему блоку, чтобы нельзя было смешать части разных переводов.

Локальный helper предоставляет аутентифицированные loopback endpoints для размера, чтения и очистки `local-service.log`. Runtime показывает размер рядом с IndexedDB-кэшем, копирует не более последних 2 МБ лога в буфер обмена и при общей очистке удаляет одновременно кэш и лог. Сами служебные обращения к логу не записываются в него.

Ссылка помощи по выбору модели не использует Electron `window.open`: runtime передаёт helper только проверенный `siteSlug`, helper сам строит канонический URL раздела `#translation-how-title` на странице игры `https://vnrevival.fun/ru/games/` и открывает его системным браузером. Произвольные origin, path и URL из игрового DOM этот endpoint не принимает.

Аутентифицированный `POST /v1/translation-metrics` принимает только строгую схему числовых показателей и перечислений. `screen.start/result` относятся к одному проходу очереди (включая кэш); времена отсчитываются через `performance.now()` после preflight, до/после записи DOM, без измерения кадра. `translation.start` содержит `screen_id`, `batch_size`, `kind`; токены и сообщённая провайдером стоимость связываются через его `request_id` с `provider.usage`. Успешные ответы helper возвращают только нормализованные счётчики usage, чтобы runtime суммировал их в `screen.result`: токены, число ответов с usage, число ответов со стоимостью и `reported_cost_usd`. `null` для стоимости означает, что провайдер её не сообщил; ноль считается известным нулём. `requests_planned` — задания после группировки до проверки кэша; `helper_requests` — реальные вызовы helper с учётом runtime-повторов, `batch_requests` — их пакетное подмножество. `cache_hits` считает строки или составные контексты, а не Text-узлы. `max_queue_wait_ms` — наибольшее ожидание задания до worker. Итог может быть `complete`, `failed`, `cancelled` или `superseded` при смене настроек. Ошибка записи метрик не прерывает перевод; содержимое текста и настроек не принимается этой схемой.

Существующие CoC2 Google-ключи v1/v2 читаются как fallback и лениво заменяются v3 после успешной записи. Для OpenAI-compatible legacy fallback не применяется. Метаданные количества/байтов защищены dirty-маркером и при расхождении восстанавливаются потоковым курсором.

Кэш не является пользовательским форматом обмена. Runtime хранит и обслуживает его локально; публичный интерфейс предоставляет только безопасную полную очистку.

Функция сбора запросов не показывается в панели, а runtime не вызывает `/v1/capture/*`. Обычная работа переводчика не создаёт `translation-capture.json`. В helper оставлен изолированный диагностический API: он доступен только локальному клиенту с токеном текущего запуска и требует явного `accepted: true` для старта и очистки. Сбор выключен при каждом запуске helper; API не вызывает провайдер и не пишет содержимое набора в обычный лог. Этот API не является публичным пользовательским контрактом.

## Пакет скриншотов

Пользовательская кнопка запускает последовательный проход по каноническому списку локалей, поддерживаемых выбранным провайдером. Runtime временно выключает автоперевод без сохранения промежуточных настроек, для каждой локали восстанавливает исходные Text nodes, выполняет полный перевод текущего экрана и ждёт загрузки шрифтов и двух кадров. На время снимка панель скрыта, а отдельная метка в Shadow DOM показывает точный код локали. После прохода runtime восстанавливает язык, режим показа и автоперевод, повторно приводит DOM к исходному состоянию пользователя и только затем завершает пакет.

Launcher передаёт helper порт CDP и manifest hints уже выбранного игрового target. Аутентифицированный `POST /v1/screenshots/capture` повторно находит page target только на том же `127.0.0.1:<cdp-port>` и вызывает `Page.captureScreenshot` через WebSocket. Helper не принимает путь назначения от DOM: он создаёт каталог внутри собственного `data-dir/screenshots`, проверяет batch ID, locale и единый номер пакета, и сохраняет PNG как `<locale>-<number>-Gameplay.png`. `finish` сверяет фактическое число файлов, а `open` может открыть только каталог активного в этом процессе batch.

`screenshots-evidence.json` записывается атомарно и содержит версию переводчика и игры, размеры, количество байтов, SHA-256 и время каждого снимка. Автоматическое завершение доказывает целостность пакета, но не качество локализации: успешный результат имеет статус `capture-pass-review-pending` до отдельной визуальной проверки.

## Launcher-инварианты

Windows-лаунчер — единый Win32 x86-64 GUI без консоли и прав администратора. Он работает нативно на Windows 10/11 x64 и через встроенную эмуляцию x64-приложений на Windows 11 on Arm. Лаунчер использует сохранённый путь, ищет Steam-библиотеки и AppID, показывает `GetOpenFileNameW`, запускает комплектный x86-64 embeddable Python helper, подключается через WinHTTP WebSocket и завершает helper при закрытии игры или исчезновении CDP target три проверки подряд. В пакете нет драйверов и дополнительных нативных расширений; отдельный Arm-архив не создаётся.

macOS launcher требует CrossOver и запускает только Windows-версию игры из бутылки CrossOver. Steam-копия запускается только через Steam с ожиданием до двух минут, без прямого fallback на EXE; сохраняются системный выбор файла и путь по `game-id`; локальный helper запускается системным Python при его наличии. Parallels, виртуальные машины и комплектный Windows payload не входят в macOS-приложение.

Windows ZIP содержит только официальный x86-64 embeddable Python и standard-library helper — переводческих движков, моделей и дополнительных runtime-пакетов нет. Сборка macOS объединяет `arm64` и `x86_64`, поддерживает ad-hoc/Developer ID signing и нотариальное заверение; Windows поддерживает Authenticode. `VNREVIVAL_APP_ONLY=1` создаёт проверяемую локальную CrossOver-only `.app` без сборки Windows payload и без релизных архивов.
